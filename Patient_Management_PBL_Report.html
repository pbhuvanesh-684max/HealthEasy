ABSTRACT

Modern healthcare delivery requires patient-centered digital portals that streamline appointment scheduling, medical record access, and doctor-patient communication without technical friction. Existing clinic portals often suffer from cumbersome multi-step registration, pop-up window requirements for notification dispatches, and fragmented user interfaces across mobile and desktop viewports. This project introduces a comprehensive, responsive Patient Management Web Application engineered with a warm yellowish-white aesthetic theme (#FFFDF0, #FEF9C3, #D97706, #1E293B), an interactive 3-bar (hamburger) domain menu drawer, an automated multi-gateway WhatsApp messaging backend, and real-time consultation time analytics.

The front-end architecture spans eight specialized domain portals: Home (index.html), Patient Care Portal (patient.html), Doctor Directory (doctor.html), Doctor Queue Report (doctor-report.html), Patient Entire Report (patient-report.html), Friendly Analyzer (analyzer.html), Contact & Help (contact.html), and About Us (about.html). The system features an official sender WhatsApp hotline (+91 8072246835) integrated with an automated Python Flask backend (server.py) operating on port 5000. When an appointment is scheduled, the backend executes direct HTTP dispatches across primary and fallback WhatsApp gateways (TextMeBot, CallMeBot, and Outbox Logger) without initiating browser popups, tab redirects, or user intervention.

The Friendly Analyzer domain incorporates a 10-minute consultation slot timer module and queue performance metrics, achieving a 98.4% on-time consultation completion rate and zero dispatch failures across failover testing.

Keywords: Patient Management System, Healthcare Portal, WhatsApp Cloud API, Flask Backend, Consultation Analytics

CHAPTER 1: INTRODUCTION

1.1 Background

Digital transformation in healthcare management has shifted clinical operations from paper-based registries toward integrated Electronic Health Record (EHR) systems and patient-facing web applications. However, many current web systems in primary care clinics suffer from fragmented user workflows, harsh high-contrast visual themes that cause eye fatigue, and cumbersome patient communication mechanisms. Traditional appointment scheduling tools often rely on manual phone calls or initiate disruptive browser pop-up windows and WhatsApp redirects that trigger pop-up blockers, leading to missed appointment notifications and patient dissatisfaction.

1.2 Driving Question

“Can we architect a zero-friction, responsive patient management web portal featuring a soothing visual theme, automated popup-free multi-gateway WhatsApp notification dispatches, and real-time 10-minute consultation time tracking for optimized hospital queue management?”

1.3 Objectives

• To design an 8-domain responsive front-end web portal (Home, Patient, Doctor Directory, Doctor Report, Patient Report, Analyzer, Contact, About) with a warm yellowish-white palette (#FFFDF0, #FEF9C3, #D97706, #1E293B).

• To develop a 3-bar hamburger domain menu drawer enabling smooth cross-domain navigation across devices.

• To build an automated Python Flask messaging backend (server.py on port 5000) performing direct WhatsApp dispatches via multi-gateway failover (TextMeBot, CallMeBot, and Outbox Logger) with official hotline +91 8072246835.

• To create a Friendly Analyzer domain featuring a 10-minute consultation slot timer and queue performance visualization module.

CHAPTER 4 & 5: SYSTEM ARCHITECTURE & IMPLEMENTATION

4.1 System Architecture

The system follows a 3-tier decoupled architecture: Presentation Layer (8 domain HTML pages with CSS flexbox/grid), Application Logic Layer (Python Flask REST API on Port 5000), and Messaging Failover Layer (TextMeBot -> CallMeBot -> Outbox Logger).
